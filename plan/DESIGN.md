# Design: fieldNote - 네이버 지도 GPX 경로 그리기 도구

## Problem Statement

한국에서 경로를 그려서 GPX로 내보내려면 gpx.studio 같은 도구를 써야 하는데, 전부 OSM 기반이라 한국 지도가 약하다. 네이버 지도 위에서 클릭으로 경로를 그리고, 여러 경로를 색상별로 관리하고, GPX 파일로 내보내기/가져오기할 수 있는 도구가 없다.

## What Makes This Cool

한국 사용자에게 딱 맞는 빈 자리. 네이버 지도의 정확한 한국 지형 데이터 위에서 직접 경로를 그리고 관리할 수 있다. 기존 도구들이 전부 해외 지도 기반이라 한국 도로/건물/지명이 엉성한 문제를 정면으로 해결한다.

## Constraints

- 클라이언트 전용, 서버/DB 없음
- Vercel 정적 배포
- 네이버 지도 API v3 (NCP) - 월 6만건 무료
- 부동산 기능 제외, 순수 경로 그리기 도구
- 다크 모드, 왼쪽 사이드바 레이아웃 (variant-B)

## Premises

1. 네이버 지도 API v3 (NCP) 사용 — API 키 발급 필요, 월 6만건 무료
2. 서버 없이 클라이언트만으로 동작 — DB 불필요, 정적 호스팅(Vercel)으로 배포
3. 부동산 기능 제외, 순수 경로 그리기 도구 — 여러 경로 색상별 구분, 거리/시간 표시, GPX 내보내기/가져오기

## UI 디자인: variant-B (다크 모드, 왼쪽 사이드바)

### 레이아웃
```
+------------------+----------------------------------------+
|  fieldNote       |                                        |
|                  |                                        |
|  [+새 루트]      |                                        |
|  [GPX 불러오기]   |          네이버 지도                     |
|  [GPX 다운로드]   |          (전체 영역)                     |
|                  |                                        |
|  ● 루트 1  2.3km |                                        |
|  ● 루트 2  1.8km |                ~~~~경로~~~~             |
|  ● 루트 3  0.5km |                                        |
|                  |                                        |
+------------------+----------------------------------------+
  사이드바 (~240px)          지도 (나머지 전체)
```

### 다중 경로 관리 UI
- 사이드바에 루트 리스트: 색상 점(●) + 이름 + 거리
- 클릭하면 활성 루트 전환 (활성 루트 하이라이트)
- 각 루트에 이름 변경, 삭제 기능
- "+새 루트" 버튼으로 새 경로 추가 (자동으로 다음 색상 배정)
- 색상 팔레트: 6색 고정 (`#FF6B35`, `#4DABF7`, `#51CF66`, `#CC5DE8`, `#FF6B6B`, `#FFD43B`), 초과 시 인덱스 모듈로 순환

### 상호작용
- 지도 클릭 → 활성 루트에 웨이포인트 추가
- 웨이포인트 드래그 → 위치 이동
- 웨이포인트 우클릭/더블클릭 → 삭제
- 폴리라인으로 웨이포인트 직선(straight-line) 연결, 실시간 거리 계산 (세그먼트별 Haversine 합산)
- 도로 스냅(road-snapping)은 v1 스코프 외 — Directions API 추가 호출 필요

## Recommended Approach

**Next.js + 컴포넌트 구조** (이전 세션에서 Approach B로 선택됨)

### 기술 스택
- **프레임워크:** Next.js (App Router)
- **스타일링:** Tailwind CSS (다크 테마)
- **지도:** 네이버 지도 API v3 (NCP) - `next/script` (`strategy="afterInteractive"`, `onReady` 콜백)
- **GPX 처리:** 브라우저 DOMParser (파싱) + 수동 XML 생성 (내보내기)
- **상태 관리:** React Context + useReducer
- **배포:** Vercel 정적 배포 (`next.config.ts`에 `output: 'export'` 설정)

### 주의사항
- `NaverMap.tsx`는 `'use client'` 필수 — 네이버 지도 API가 `window`/`naver.maps` 글로벌 객체에 의존
- `output: 'export'`이므로 API Routes 사용 불가 (이 프로젝트는 서버 기능 불필요하므로 문제 없음)
- GPX 파싱 에러 시 사용자에게 토스트/알림으로 피드백 (잘못된 XML, 빈 경로, 좌표 범위 초과 등)
- localStorage로 작업 내용 자동 저장 (브라우저 닫아도 데이터 보존)
  - 저장 시점: 루트 추가/삭제, 웨이포인트 변경 시 디바운스(500ms)로 자동 저장
  - 키: `fieldnote-state`, 값: JSON.stringify(AppState)
  - 앱 로딩 시 localStorage에서 복원
- 네이버 지도 클라이언트 ID는 `NEXT_PUBLIC_NCP_CLIENT_ID` 환경변수로 주입
- GPX 다운로드: 전체 루트를 하나의 GPX 파일에 복수 `<trk>`로 내보내기
- 정적 빌드에서 `next/script` + `onReady` 동작을 구현 초기에 검증할 것

### 컴포넌트 구조
```
app/
  layout.tsx          — 전역 레이아웃 (다크 테마)
  page.tsx            — 메인 페이지 (사이드바 + 지도)
  globals.css         — Tailwind + 다크 테마 변수

components/
  Sidebar.tsx         — 왼쪽 사이드바 컨테이너
  RouteList.tsx       — 루트 목록 (리스트 + 색상 점)
  RouteItem.tsx       — 개별 루트 항목 (이름, 거리, 색상, 삭제)
  Toolbar.tsx         — 상단 버튼 (+새 루트, GPX 불러오기/다운로드)
  NaverMap.tsx        — 네이버 지도 래퍼 컴포넌트

lib/
  RouteContext.tsx    — 루트 상태 관리 (Context + Reducer)
  gpx.ts              — GPX 파싱/생성 유틸리티
  naverMap.ts         — 네이버 지도 헬퍼 (폴리라인 생성, 거리 계산)
  colors.ts           — 루트 색상 팔레트

types/
  route.ts            — Route, Waypoint 타입 정의
```

### 핵심 데이터 모델
```typescript
interface Waypoint {
  lat: number;
  lng: number;
  ele?: number;   // 고도 (GPX 가져오기 시 보존)
  time?: string;  // 타임스탬프 (GPX 가져오기 시 보존)
}

interface Route {
  id: string;
  name: string;
  color: string;
  waypoints: Waypoint[];
  distance: number; // 미터 단위
}

interface AppState {
  routes: Route[];
  activeRouteId: string | null;
}
```

### 구현 순서
1. **프로젝트 셋업** — Next.js + Tailwind + 다크 테마 + 네이버 지도 로딩
2. **지도 + 단일 경로** — 지도 표시, 클릭으로 웨이포인트 추가, 폴리라인 그리기
3. **다중 경로** — RouteContext, 루트 추가/삭제/전환, 색상 관리
4. **경로 편집** — 웨이포인트 드래그 이동, 삭제
5. **GPX 내보내기/가져오기** — XML 생성/파싱, 에러 토스트
6. **자동 저장** — localStorage 저장/복원, 디바운스
7. **UI 마무리** — 거리 표시, 이름 편집, 반응형

## 디자인 토큰

### 색상
- **배경 (전체):** `bg-zinc-950` (#09090b)
- **사이드바 배경:** `bg-zinc-900` (#18181b)
- **활성 루트 배경:** `bg-zinc-800` (#27272a) + 왼쪽 2px 액센트 보더
- **텍스트 (기본):** `text-zinc-100` (#f4f4f5)
- **텍스트 (보조):** `text-zinc-400` (#a1a1aa)
- **액센트:** `#FF6B35` (주황, +새 루트 버튼 등)
- **토스트 성공:** `#51CF66` 배경
- **토스트 에러:** `#FF6B6B` 배경
- **토스트 정보:** `text-zinc-400` 배경

### 타이포그래피
- **폰트:** Pretendard (한글) + Geist Sans (영문/숫자)
- **사이드바 제목:** 18px semibold
- **루트 이름:** 14px medium
- **거리 표시:** 12px regular, text-zinc-400
- **버튼 텍스트:** 13px medium

### 간격
- **사이드바 너비:** 240px
- **사이드바 내부 패딩:** 16px
- **루트 아이템 간격:** 4px
- **루트 아이템 패딩:** 8px 12px

## 사이드바 구조 (상세)

### 레이아웃 규칙
- **상단 고정 영역 (sticky):** fieldNote 로고 + 액션 버튼 (+새 루트, GPX 불러오기, GPX 다운로드)
- **스크롤 영역:** 루트 리스트만 overflow-y-auto로 스크롤
- 루트가 10개 이상이어도 액션 버튼은 항상 접근 가능

### 활성 루트 표시
- 사이드바: bg-zinc-800 + 왼쪽 2px 액센트(#FF6B35) 보더
- 지도: 활성 루트 폴리라인 3px, 비활성 2px

### 루트 이름 편집
- 더블클릭 → input으로 변환 → Enter/blur로 확정
- 편집 중 Escape로 취소

### 루트 삭제
- 각 루트 아이템에 호버 시 삭제(×) 버튼 표시

## 지도 컨트롤

- 네이버 지도 기본 컨트롤 숨김 (다크 모드 일관성)
- 커스텀 줌 +/- 버튼 (지도 우하단, 다크 테마 스타일)
- 지도 타입 전환은 v1 스코프 외

## 웨이포인트 마커 디자인

- 경로 색상과 동일한 8px 원형 마커
- 흰 테두리 1px (다크 지도에서 식별성 확보)
- 드래그 시 12px로 확대
- 네이버 기본 마커 사용 안 함

## 인터랙션 상태

### 빈 상태 (Empty State)
- 처음 열면 '루트 1'이 자동 생성됨
- 사이드바에 "지도를 클릭해서 경로를 그려보세요" 안내 메시지
- 지도 중앙에 반투명 힌트 오버레이 (첫 웨이포인트 추가 전까지만)

### 로딩 상태
- 네이버 지도 로딩 중: 다크 배경(#09090b) + 중앙 스피너 애니메이션
- 지도 로드 실패 시: 에러 메시지 + "다시 시도" 버튼

### 토스트 알림
- 위치: 지도 영역 하단 중앙
- 3초 후 페이드아웃
- 성공: 초록 (#51CF66), "루트 3개 불러옴"
- 에러: 빨간 (#FF6B6B), "잘못된 GPX 파일입니다"
- 정보: 회색, "내보낼 루트가 없습니다"

### GPX 가져오기 상태
- 파일 읽는 중 → 로딩 표시 (토스트)
- 유효한 경로 없음 → "유효한 경로가 없습니다" 에러 토스트
- 성공 → "루트 N개 불러옴" 성공 토스트

### GPX 내보내기 상태
- 내보낼 루트 없음 → "내보낼 루트가 없습니다" 정보 토스트
- 성공 → 파일 다운로드 시작 + "GPX 다운로드 완료" 성공 토스트

### localStorage 복원
- 앱 시작 시 자동 복원 시도
- 복원 실패 → 무시하고 새로 시작 (빈 상태)
- 복원 성공 → 이전 상태 그대로 표시 (별도 알림 없음)

## Undo 기능

- Ctrl+Z (Mac: Cmd+Z)로 마지막 웨이포인트 삭제
- 여러 번 누르면 여러 개 삭제 (스택 기반)
- 활성 루트의 웨이포인트에만 적용
- v1에서는 웨이포인트 추가만 undo 대상 (삭제/이동의 undo는 v2)

## 반응형 & 접근성

### 반응형
- **v1: 데스크톱 전용** (최소 너비 1024px)
- 1024px 미만 접속 시: "데스크톱에서 사용해 주세요" 안내 표시
- 모바일 반응형(사이드바 → 하단 시트)은 v2 스코프

### 접근성 (최소)
- 키보드: Tab으로 사이드바 탐색, Enter로 루트 선택, Delete로 웨이포인트 삭제
- 색상 대비: WCAG AA 준수 (다크 배경 위 밝은 텍스트)
- 경로 색상이 색맹 사용자에게도 구분되도록 6색 팔레트 검증

## What I noticed about how you think

- 디자인을 직접 보여주고 친구 피드백까지 받아서 결정했다. 빠르게 움직이면서도 외부 검증을 거치는 습관.
- variant-B를 선택하면서 다중 경로 지원을 명확하게 요구사항으로 추가했다. 목업의 한계를 알고 기능 사양을 분리해서 생각할 줄 안다.
- 부동산 기능을 깔끔하게 스코프에서 제외한 결정. 범위를 좁히는 감각이 있다.
